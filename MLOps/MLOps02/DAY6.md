## 2. 각 섹션 체크포인트의 답변


### 섹션 1
1. 1.인증없는 API가 위험한 이유를 두 가지 이상 설명하세요. 
   무단 사용으로 서버 과부하나 클라우드 추론 비용이 폭발적으로 청구될 수 있고 모델 자산이 탈취되거나 로그,감사가 불가능하고, 오'남용이 발생해도 특정할 수 없음
2. 2.API Key 방식이 ML추론 API에 적합한 이유는 무엇입니까?
   서버 간 자동 호출에 용이하고 빠른 단일 요청, 응답이 많은 환경에서 인증 오버헤드가 작아서 구현이 단순하고 사용량 추적, 요금 부과와 제한이 쉽다. 또한 발급과 폐기가 간결하여 ML추론API의 특성에 적합함



### 섹션 2
1. 1.Header(None)에서 None은 어떤 상황에서 x_api_key에 들어갑니까?  
   요청에 x_API_key 헤더가 없을 때 None이 들어가고 이는 "인증 정보 미제공"을 나타냄 

2. 2.Depends(verify_api_key)를 엔드포인트에 추가하면 요청 처리 흐름이 어떻게 바뀝니까?  
 모든 요청이 추론에 닿기 전에 인증을 통과해야 합니다 (관문 추가).
인증 실패 시 추론 코드는 아예 실행되지 않아, 무단 사용으로 인한 리소스 낭비를 막고(앞서 말한 1차 방어선) 성공 시 검증된 사용자 정보(user)가 엔드포인트로 전달되어, 로깅·사용량 추적 등에 활용할 수 있습니다.


3. 인증 실패 시 반환하는 HTTP상태 코드 401의 의미는무엇입니까?
   401은 "인증 자격 증명이 없거나 틀렸다" 는 뜻으로, 클라이언트가 올바른 API Key를 담아 다시 요청해야 함을 알려주는 신호






### 섹션 4
1. UploadFile과 Base64 방식의 핵심 차이는 무엇입니까?
   UploadFile은 바이너리를 그대로/스트리밍으로 다뤄 대용량에 효율적이고, Base64는 텍스트로 변환되어 크기·메모리 비용이 크다.

2. file.content_type으로 타입을 검증하는 이유는 무엇입니까?  
  서버가 기대하는 형식의 파일만 받기 위해서이고 잘못된 형식의 파일이 처리 로직에 들어가 발생하는 에러·오작동을 사전 차단하고 악의적 파일 업로드에 대한 1차 방어선

3. 파일 크기를 제한하지 않으면 어떤 문제가 발생할 수 있습니까?  
  거대한 파일이 서버 자원을 소진하여 메모리/디스크 고갈되고  공격자가 대용량 파일을 반복 업로드해 서비스 마비시킬 수 있고 응답 처리 시간 증가로 다른 요청까지 영향을 주며 비용 증가됨

### 섹션 6(최종 체크포인트)
   
Q1. API Key 인증이 없으면 어떤 위험이 있습니까? (두 가지 이상)
무단 사용 — 누구나 API를 호출해 자원(GPU/연산)을 소모 → 비용 폭증
DoS/과부하 — 무제한 요청으로 서버 마비
데이터 유출·악용 — 모델 결과나 내부 기능에 인증 없이 접근
사용량 추적 불가 — 누가 얼마나 썼는지 식별·제한 불가

Q2. Depends(verify_api_key)는 엔드포인트 실행 전에 어떤 일을 합니까?
엔드포인트 함수가 실행되기 전에 먼저 verify_api_key를 호출
요청 헤더의 API Key를 검사 → 유효하지 않으면 401 등 에러로 차단하고 본 로직은 실행되지 않음
유효하면 통과시켜 엔드포인트 실행 (의존성 주입 기반의 공통 인증 전처리)

Q3. UploadFile 방식이 Base64보다 편리한 점은 무엇입니까?
크기 효율 — Base64처럼 약 33% 커지지 않고 원본 그대로 전송
메모리 효율 — 디스크에 스풀링되어 대용량 파일도 처리 가능
추가 인코딩/디코딩 불필요 — 파일을 바로 받아 사용
파일명·content_type 등 메타데이터를 함께 받을 수 있음

Q4. 파일 업로드 시 크기 제한을 하지 않으면 어떤 문제가 생깁니까?
메모리/디스크 고갈로 서버 다운
대용량 반복 업로드를 통한 DoS 공격에 취약
응답 지연·타임아웃으로 다른 요청까지 영향
저장소·대역폭 비용 증가

Q5. 이미지를 28x28 그레이스케일로 변환하는 이유는 무엇입니까?
모델(예: MNIST)이 28x28 흑백 이미지로 학습되었기 때문 → 입력 형식을 학습 데이터와 맞춰야 함
색상 정보가 불필요해 채널을 1개로 줄여 연산량·데이터 축소
모든 입력을 동일한 크기·형식으로 정규화해 일관된 추론 가능
